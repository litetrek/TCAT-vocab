# T2.1 執行提示詞 — 逐章上傳 + AI 主題分組（可中途儲存）

> 使用方式：將以下內容整段貼給 Claude Code，在本機 repo（`C:\Users\vince\code-projects\buddhist-vocab`）內執行。T0、T1、T2 已完成。T2.1 是對 T2 匯入流程的修正：改為手動逐章上傳，並在句子級分句之後加一層「AI 主題分組」，分組結果需經人工確認才寫入正式表，且支援中途儲存進度。

---

## 背景與設計決策（已與設計者確認）

1. **章節切分**：由操作人員自己把書拆成一個個章節檔案，逐章上傳，系統不自動判斷章節邊界
2. **AI 主題分組時機**：上傳章節後立即開始（前端逐段驅動，避免 CGI 逾時），但**分組結果不直接寫入 `trans_units`**，而是先進暫存表，經人工在畫面上確認/調整（可拆句、可合併）後才正式寫入
3. **中途儲存**：人工調整過程中隨時可離開，下次回來能接續上次的進度，不會遺失
4. **權限**：本階段仍受 T2 建立的 `TRANSLATION_MIN_ROLE` 旗標保護，維持 admin-only（開發測試期間）

## 任務一：資料庫遷移

新增遷移 `006_t2_1_sentence_map.sql`：

```sql
alter table trans_units add column sentence_map jsonb;
-- sentence_map: 記錄這個翻譯單元是由哪些原始句子組成
-- 格式: [{"text": "...", "is_long_sentence": bool}, ...]
-- NULL = 單一句子的舊式單元；非 NULL = AI/人工分組後的多句合併單元

create table trans_unit_drafts (
  id bigint generated always as identity primary key,
  chapter_id bigint not null references trans_chapters(id),
  paragraph_index int not null,
  draft_groups jsonb not null,
  -- draft_groups 格式: [{"sentences": [{"text": "...", "is_long_sentence": bool}, ...]}, ...]
  -- 陣列中每個元素代表未來會成為一個 trans_units 的分組
  status text default 'pending'
    check (status in ('pending','ai_suggested','human_adjusted','confirmed')),
  last_modified_by text,
  last_modified_at timestamptz default now(),
  unique (chapter_id, paragraph_index)
);
create index idx_drafts_chapter on trans_unit_drafts (chapter_id, paragraph_index);
```

### 驗收標準（任務一）
- 遷移成功套用；`trans_units.sentence_map` 欄位存在且可為 NULL
- `trans_unit_drafts` 表建立完成，`unique(chapter_id, paragraph_index)` 約束生效（同一段落重複 upsert 應更新而非產生新列）

## 任務二：章節上傳（改為逐章、不含 AI）

### API：`POST /api/trans/books`
- 只建立書籍中繼資料（title、source_id），**不含任何文字內容**
- 若 T2 已有此端點且行為相符，確認即可；若 T2 版本仍接受整本書文字，需移除該部分邏輯

### API：`POST /api/trans/books/<id>/chapters`
- 權限：受 `TRANSLATION_MIN_ROLE` 旗標保護
- 輸入：`chapter_index`、`title`、`section_type`（或沿用既有段首關鍵字偵測，因為現在每次只上傳一章，偵測範圍縮小、準確度更高）、章節純文字內容
- 流程：
  1. INSERT 一筆 `trans_chapters`
  2. 呼叫 T1 的 `segmenter.py` 對這章內容做空行分段 + 句子切分（**這一步是純演算法，不呼叫 AI，可以整章一次跑完，不受 CGI 逾時限制**）
  3. 對每個段落，批次 INSERT 一筆 `trans_unit_drafts`：`draft_groups` 初始值為「每句自成一組」（也就是分句結果，尚未經過 AI 分組），`status = 'pending'`
  4. 回傳這章的段落數（供前端後續逐段觸發 AI 分組時顯示進度條）

### 驗收標準（任務二）
- 上傳一份單章測試文本，確認 `trans_chapters` 與對應的 `trans_unit_drafts`（每段一筆，`status='pending'`）都正確建立
- 引號保護、長句判斷邏輯（沿用 T1 `segmenter.py`）在此流程中依然正確

## 任務三：AI 主題分組（預覽，不寫入正式表）

### `ai.py` 新函式：`group_sentences_by_topic(sentences: list[dict]) -> list[list[int]]`
- 輸入：某段落的句子清單（`[{"text": ..., "is_long_sentence": ...}, ...]`）
- 輸出：分組後的句子索引清單，例如 `[[0,1], [2], [3,4,5]]` 代表第 0、1 句合成一組，第 2 句自成一組，第 3、4、5 句合成一組
- 沿用既有 `ai.py` 的模型封裝與錯誤處理模式，模型用 Haiku（沿用專案慣例）
- **AI 呼叫失敗時**：不可拋錯中斷，回傳退回「每句自成一組」的結果，讓後續流程能繼續（人工仍可在畫面上手動分組）

### API：`POST /api/trans/chapters/<id>/paragraphs/<idx>/group-preview`
- 權限：受 `TRANSLATION_MIN_ROLE` 旗標保護
- 讀取該段落現有的 `trans_unit_drafts.draft_groups`（此時應是「每句一組」的初始狀態）
- 呼叫 `group_sentences_by_topic()`，用回傳結果 UPDATE `draft_groups`，`status` 改為 `'ai_suggested'`
- 回傳更新後的 draft 內容給前端顯示

### 前端觸發方式
- 章節上傳完成後，前端**逐段**呼叫此端點（一段一個請求 + 進度條），絕不在單一請求內迴圈呼叫多段的 AI（沿用第七部分既有批次 AI 呼叫原則）

### 驗收標準（任務三）
- 對測試段落呼叫 group-preview，確認 `trans_unit_drafts` 的 `draft_groups` 被正確更新、`status` 變成 `ai_suggested`
- 模擬 AI 呼叫失敗（例如暫時改壞 API key 或 mock 例外），確認該段落仍能得到「每句一組」的可用結果，不會讓整個上傳流程卡住或報錯中斷

## 任務四：人工確認畫面（可中途儲存）

### API：`GET /api/trans/chapters/<id>/drafts`
- 回傳該章節目前全部段落的 draft 狀態（不論是 `pending`／`ai_suggested`／`human_adjusted`／`confirmed`），供畫面還原上次進度

### API：`PATCH /api/trans/chapters/<id>/paragraphs/<idx>/draft`
- 輸入：人工調整後的 `draft_groups`（例如把某句從一組移到另一組、拆開某一組、合併兩組）
- UPDATE `trans_unit_drafts`，`status` 改為 `'human_adjusted'`
- 前端應在**每次調整動作**（不是等使用者按下總儲存鈕）就呼叫此 API，確保真的能做到「中途離開也不遺失」

### API：`POST /api/trans/chapters/<id>/paragraphs/<idx>/confirm`
- 讀取該段落目前的 `draft_groups`
- 逐組寫入 `trans_units`：`chinese_text` = 該組所有句子文字串接，`sentence_map` = 該組完整的句子清單（供未來用既有 `/api/trans/units/<id>/split` 拆回原句）、`unit_order` 依序給值
- `trans_unit_drafts` 該筆 `status` 改為 `'confirmed'`（**保留該筆記錄，不刪除**，作為「AI 原始建議 vs 人工最終調整」的對照留存，未來可比照 T6 品質追蹤精神，分析 AI 分組準確率）
- 允許逐段確認，不需整章一次確認完（某些段落確認、某些還在調整,兩者並存不衝突）

### UI：章節審核工作區
- 逐段呈現：AI 建議的分組（用卡片視覺分群呈現句子）
- 操作：拖曳句子換組 / 拆開一組成多組 / 合併多組成一組（每個動作即時呼叫 PATCH 自動儲存，畫面上要有「已儲存」的輕量提示）
- 每段一個「確認寫入」按鈕，觸發 confirm API
- 章節層級進度指示：X / 總段落數 已確認
- 重新整理或關閉後再打開，畫面需能透過 `GET .../drafts` 完整還原上次調整到的狀態（含尚未確認的段落）

### 驗收標準（任務四）
- 對某段落做至少一次拆句、一次合併的手動調整，確認 `PATCH` 後資料庫立即反映最新 `draft_groups`
- 模擬「中途離開」：呼叫 `GET .../drafts` 確認能拿回剛才調整到一半的狀態（不必真的重啟瀏覽器，驗證 API 層面資料有正確持久化即可）
- 確認寫入後，檢查 `trans_units` 的 `chinese_text`、`sentence_map` 內容是否與畫面上最終呈現的分組一致（例如一組 3 句合併，`sentence_map` 應有 3 筆對應資料）
- 章節內部分段落確認、部分仍在調整中的狀態可以並存，不互相干擾
