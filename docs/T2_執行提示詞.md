## 背景

T1 的資料層與分句模組已就緒。T2 要做的是「匯入書籍」與「瀏覽」兩件事：上傳中文書 → 呼叫 T1 的 `segmenter.py` 分段分句 → 寫入 trans_books/trans_chapters/trans_units；書單 Picker 頁；唯讀的逐章句子瀏覽畫面。

**重要前提**：目前系統已在對其他成員做「詞彙」「擷取」兩個模組的宣導與培訓，「翻譯」模組仍在開發測試階段，**在正式上線前只能讓 admin（設計者本人）看到與操作**，其他角色完全不能看到「翻譯」這個頂層 Tab、也不能透過 API 存取。這件事必須是**任務一**，且必須先做完、驗證過，才能做後面的匯入/瀏覽功能——避免功能做到一半、還沒收尾就已經有其他角色能摸到。

## 任務一：開發期存取旗標（優先做，且為前置條件）

請先找到既有權限判斷的寫法（既有「詞彙」「擷取」模組的角色檢查邏輯、既有的兩層 Tab UI 導覽模板、`routes/translate.py` 是否已存在），了解慣例後，實作一個**單一集中的開關**，不要在各處寫死 `if role == 'admin'`：

1. 在設定/權限模組（例如 `auth.py` 或既有等價檔案）新增：
   ```python
   TRANSLATION_MODULE_MIN_ROLE = os.environ.get('TRANSLATION_MIN_ROLE', 'admin')

   def can_access_translation_module(user_role: str) -> bool:
       role_order = ['viewer', 'depositor', 'member', 'leader', 'admin']
       return role_order.index(user_role) >= role_order.index(TRANSLATION_MODULE_MIN_ROLE)
   ```
2. `.env` 新增 `TRANSLATION_MIN_ROLE=admin`（開發期預設值）。日後正式上線時，只需把這個值改成 `viewer`（對應設計文件第九部分的權限映射表），不需要改任何程式碼。
3. **導覽列**：頂層「翻譯」Tab 只在 `can_access_translation_module(current_user.role)` 為真時才 render；其他角色登入後應完全看不到這個分頁（不是灰階禁用，是直接不出現）。
4. **API 層必須同步擋，不能只藏 UI**：本任務接下來會新增的所有 `routes/translate.py` 端點，都要加上同一個檢查（decorator 或 route 開頭的 guard）。就算 Tab 被隱藏，非 admin 角色直接打 API 網址也必須被擋下（回傳 403）。

### 驗收標準（任務一）
- 以非 admin 帳號（viewer/member/leader 皆測一次）登入，確認：導覽列看不到「翻譯」Tab；直接訪問翻譯模組頁面網址被導向/擋下；直接呼叫任一 `/api/trans/...` 端點回傳 403
- 以 admin 帳號登入，確認：可正常看到「翻譯」Tab 並操作
- 把 `.env` 的 `TRANSLATION_MIN_ROLE` 暫時改成 `viewer` 測試一次，確認 viewer 角色能看到 Tab（唯讀），改回 `admin` 後恢復原狀
- 此任務通過後才繼續下面任務二、三

## 任務二：匯入書籍

### API：`POST /api/trans/books`
- 權限：admin（受任務一旗標控制；正式上線後設計文件原定 member+）
- 流程：接收上傳的中文 .txt → 呼叫 T1 的編碼偵測 → 呼叫 `segmenter.py` 做空行分段、段首 section_type 偵測、段內分句 → 單一 transaction 批次 INSERT 建立 `trans_books` 一筆、對應多筆 `trans_chapters`、對應多筆 `trans_units`
- `trans_units.unit_order` 依段內順序給整數值（1, 2, 3...），為之後拆句預留小數空間
- display_id 依序列自動產生（沿用 T1 已建好的 `seq_books_display` / `seq_chapters_display` / `seq_units_display`）

### API：`GET /api/trans/books`
- 權限：admin（同上，受旗標控制）
- 回傳書單，含每本書的章節進度統計（一句 SQL GROUP BY 依 status 計數，不要在 Python 迴圈裡逐章查詢）

### 驗收標準（任務二）
- 上傳一份實際的中文 .txt 測試檔（可用現有 Extraction 模組已有的測試文本，或請提供一份），確認整本書成功建立 book/chapters/units
- 驗證段首 section_type 偵測正確（「本社按」「譯者序」等開頭有標記）
- `GET /api/trans/books` 回傳的進度統計數字與資料庫實際 COUNT 一致

## 任務三：瀏覽（唯讀）

### API：`GET /api/trans/chapters/<id>/units`
- 權限：admin（受旗標控制）
- 回傳該章節底下依 `paragraph_index, unit_order` 排序的全部句子（含 status）

### UI：Picker 頁
- 書單卡片：書名、章節數、整體進度條、依 status 分類的數量統計色標（灰 untranslated／藍 ai_drafted／金 in_review／橙 revised／綠 approved）
- 「上傳新書」表單（觸發任務二的上傳 API）

### UI：章節唯讀瀏覽頁
- 逐句列表：display_id、中文原句、status 色標
- 純唯讀，不含編輯、AI 翻譯按鈕（那是 T3 範圍）

### 驗收標準（任務三）
- 整本書可上傳、可在 Picker 看到、可逐章點進去瀏覽全部句子
- 色標、進度條數字與資料庫實際狀態一致
